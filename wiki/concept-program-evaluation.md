# Program Evaluation

Research asks "**is this true in general?**" — it seeks knowledge that generalizes beyond the people studied. **Program evaluation** asks a narrower, more local question: "**is *this* program, in *this* setting, worth it — and how do we make it better?**" You will meet this the moment you work anywhere with a service to justify: a school counseling program, an agency's substance-use group, a campus wellness initiative, a grant-funded pilot. Someone will ask whether it's working, and "the clients seem to like it" won't survive a funder, a school board, or a CACREP site visit. Program evaluation is the second half of this unit's CACREP area for a reason — accreditation explicitly requires counselors to run **needs assessments**, build **outcome measures**, and **evaluate interventions and programs** [S21].

## Evaluation vs. research: same tools, different aim

Program evaluation borrows the whole methods toolkit — designs, measures, effect sizes, the validity checklist — but its **purpose** differs, and that difference matters [S17]:

- **Research** aims for **generalizable knowledge** — findings meant to apply beyond the sample, published for the field.
- **Program evaluation** aims for a **judgment of merit or worth** about a **specific** program, for **local decision-making** (continue it? fund it? fix it?).

The practical consequences: evaluation is driven by **stakeholders' questions** (the funder's, the director's, the clients'), it's bounded to one program rather than generalized, and — a useful rule of thumb — internal quality-improvement evaluation often does **not** require IRB review the way research does, though the ethics of consent and confidentiality ([[concept-irb-research-ethics]]) still apply. (When findings will be **published as generalizable knowledge**, it becomes research and IRB review re-enters.)

## The types of evaluation — a "which stage?" set

The confusable set to keep straight (this is what the unit interleaves) is **when** in a program's life an evaluation happens and **what** it asks [S17]:

- **Needs assessment** — done **before** you build: what's actually needed, and by whom? Prevents solving the wrong problem.
- **Formative evaluation** — done **during** development/early implementation: gather information to **improve and strengthen** the program while it's still malleable.
- **Process (implementation) evaluation** — asks whether the program was **delivered as intended, to the intended people**: attendance, fidelity, dose, reach. (A program can "fail" simply because it was never really delivered — process evaluation catches that before you wrongly blame the model.)
- **Summative evaluation** — done **at/near the end**: a final judgment of the program's overall **worth and outcomes** — continue, expand, or cut?
- **Outcome / impact evaluation** — did the **targeted conditions actually change** (symptoms, retention, well-being), and can the change be attributed to the program?

The clean mnemonic: **formative = steering the ship mid-voyage; summative = judging the whole trip once you've arrived.** And the orthogonal cut: **process** asks *was it done right?*, **outcome** asks *did it work?* — a program can pass one and fail the other (delivered perfectly but ineffective; or effective despite sloppy delivery), which is exactly why you look at both. Counselors, surveyed, report doing **single-case** and **outcome** evaluation most often [S17].

## The accountability loop

Good program evaluation is a **cycle**, not a one-time report: assess needs → set measurable goals → deliver the program → measure process and outcomes → **feed the results back** into revising the program. This is the program-level echo of two things you've already built — Unit 7's **golden thread** ([[concept-treatment-planning]]: assessment → goal → intervention → review) and the individual-level **measurement-based care** loop of [[concept-single-case-design]]. Same logic — set a target, measure toward it, revise — at the level of a whole service rather than one client. Counseling-specific accountability models (e.g., the Accountability Bridge) formalize exactly this loop [S17].

## The stance for program evaluation

Two cautions carry over from the rest of the unit. First, **measurable is not the same as meaningful** (Unit 7): a program can hit easy attendance targets while doing nothing for the outcomes that matter, so choose outcome measures that capture the change you actually care about, not the ones easiest to count. Second, **evaluation is for improvement, not just judgment** — its most valuable products are usually formative and process findings that tell you *how* to make the service better, not a summative thumbs-up/down. Used well, it protects clients (by catching programs that don't help) and protects good programs (by giving them the evidence to survive a budget cut). Used badly — as pure box-checking — it becomes the accountability theater the syllabus's "evidence-based practice is an expectation, not a slogan" line warns against.
